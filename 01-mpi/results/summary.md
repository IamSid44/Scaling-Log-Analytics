# MPI benchmark results

Median over the repetitions in `benchmark.csv`, timed with `MPI_Wtime` on the slowest rank.

`t_solve` = read + parse + aggregate + reduce. `t_comm` is time inside MPI calls *after* a barrier has absorbed straggler wait; that wait is reported separately as load imbalance.

> **Placement.** Every other row is one rank per node, so P is the number of machines. The exception is P=8 on 4 nodes (2 ranks/node) -- the allocation had fewer machines than ranks, so those ranks were packed. That point is not comparable with the rest: co-resident ranks keep part of their collectives in shared memory, but they also share one machine's memory bandwidth and page cache. For a bandwidth-bound workload like this one the contention dominates, so the packed point can sit *below* the one-per-node trend rather than above it.
