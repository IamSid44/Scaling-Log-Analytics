## 6. Memory

Peak resident memory (RSS) of one process, measured with `getrusage` (MPI, MapReduce on the cluster) or YARN's container counters (Hadoop, whole container: JVM + our C++ child).

| Process (N = 50M) | peak RSS (MB) | note |
|---|:---:|:---:|
| Sequential C++ (`loganalytics_seq`) | 10.6 | -- |
| MPI rank (max over ranks) | 33.2 | 203 MB for all 7 ranks |
| MapReduce map task (`mr_map`) | 11.1 | per task |
| MapReduce reduce task (`mr_reduce`) | 10.8 | per task |
| Hadoop map container (JVM + `mr_map`) | 342 | per task |
| Hadoop reduce container (JVM + `mr_reduce`) | 235 | per task |

Memory does not grow with N for any of them: every process holds an aggregate of size O(servers + endpoints + intervals), never the records. MPI's ~27 MB is mostly the MPI library itself. A real Hadoop map container is ~13x an MPI rank and ~30x our C++ mapper alone, because of the JVM that feeds it -- before counting the four daemons (NameNode, DataNode, ResourceManager, NodeManager) that must also be running.

## 7. Communication and data movement

| P | MapReduce: records shuffled | MapReduce: KB shuffled | MPI: KB reduced (analytical) |
|---|:---:|:---:|:---:|
| 1 | 2019 | 50 | 0 |
| 2 | 4038 | 100 | 20 |
| 3 | 6057 | 149 | 41 |
| 4 | 8076 | 193 | 61 |
| 5 | 10095 | 241 | 81 |
| 6 | 12114 | 289 | 102 |
| 7 | 14133 | 336 | 122 |
| 8* | 16152 | 384 | 142 |

N = 50M, 1894 MB of input. Both designs aggregate *before* communicating, so neither moves more than ~0.05% of the input, and neither volume depends on N (the shuffle is ~2,019 records per mapper at every size). MapReduce moves its intermediate data as text through the file system (map output written, then read by the reducers, then job 1's output read by job 2); MPI moves binary int64 arrays over the network in one collective. MPI figure: 20832 bytes per non-root rank, from the reductions in `loganalytics_mpi.cpp`.

The bigger data movement in MapReduce is the **input**: staging rewrites the whole file (§5), and every map task then reads its split from `/home` over NFS. Real HDFS would make most map reads local (data locality); the Slurm simulation cannot.
